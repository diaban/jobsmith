## From “Jobs layer (`jobs/`)”

**A list it claims to support, it must not silently reshape** (#76). `line.strip()` ran *before* the bullet match, so indentation was gone by the time an item was recognised and every level collapsed into one flat `<ul>` — measured on a real deliverable, 27 indented lines at one rank, the line introducing a group rendered as its sibling. That is not "tables or links": the renderer already claims lists, and flattening one changes what the document *says* while looking like a document. It is also why the fix is one fix — `PdfReport` prints the same page (#34), so HTML and PDF were wrong together and are right together. Three decisions. **The indentation rule is written down, not inferred per document** (`_list_level`): one level every two spaces, a tab advancing to the next level boundary (so a leading tab is one level, exactly as two spaces are), anything in between rounding down — a model that indents by three is nesting, not un-nesting. Inferring the unit from the first nested item instead would teach the renderer a unit the rest of the document does not use. **The depth comes from the stack of open lists, never from the document**: `add_item` clamps to `min(level, len(stack))`, so a jump from level 0 to level 3 opens exactly one level and no indentation a model can write leaves a tag unbalanced — the renderer's whole safety argument is that only our own tags are ever added, and an unbalanced one is that argument failing. **A nested list is opened *inside* the item above it**, by taking that item's `</li>` back (`open_list`), rather than started beside it as a `<ul>` no `<li>` contains; a flat list therefore renders byte for byte as it did, which is what `test_a_flat_list_is_unchanged` pins. Escaping is untouched — content escaped first, our own tags after — and the nested case is asserted on that too, because nesting adds tags of ours and must add none of the model's.
