## From “Jobs layer (`jobs/`)”

**The request decides what the document is called, titled and written as** (#55). `Job` carries `document_name` / `document_title` / `formats` next to `query` and `inputs` — facts about the job, recorded once, never re-derived at write time — and all three are independent: a name is not a title and neither is a format, so asking for one never silently answers the others. `FileReporter.path_for` takes the name and puts a named deliverable in **the job's own folder** (`<reports_dir>/<job_id>/<name>.<ext>`, where its annexes already are): a job id is unique and says nothing, a name says everything and is unique to nobody, and a second job called `rapport` overwriting the first is #28's "a deliverable nobody can find" from the other end. An unnamed job writes exactly where it always did. Per-job formats compose through `JobManager.reporter_factory` — a factory, not a second reporter, because what the composition root knows (the registry, `with_annexes`) has to reach a reporter built later. **Both refusals happen in `create_job`**, the last point at which whoever asked is still listening: a name that is not one path component (`document_stem` → `core/paths.py`, the same `safe_name` #60 answered the reading side with) and a format nothing can render here (`ensure_formats_available`, which composes and throws away — `.[pdf]` needs pango/cairo where the daemon runs). Refusing at the write instead would refuse three minutes and a full ledger later. The chat proposes all three and shows them before the run starts — on the `job_started` notice since #83, on the approval card where that gate was kept (`chat/tools.py`) — because a name the user never saw is exactly the second silent decision this fixes; `AgentService.launch_job` takes the same three, and the 400 the API answers maps back to the same `ValueError` on the remote backing.
