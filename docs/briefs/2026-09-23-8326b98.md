## What landed

- **#95 — The answer comes back in the conversation, and the file stops being about the run** (closes #85): a promoted run's answer is delivered verbatim in the chat like a synchronous one; the report file is now title, answer and one line naming the job.
- **#94 — A follow-up job references the job, not the file it wrote** (closes #74): "make a one-pager out of that report" reads the earlier run's answer and per-step material through a `PriorJobSource` port, scoped to the session.

- **#101 — Cross-process ownership and cancellation** (closes #10): a lease on the record says which process runs a job, a second process no longer declares it dead, and a cancel reaches the owner wherever it runs.
- **#99 — An unconfigured jobsmith keeps its jobs** (closes #63): the default persistence is a SQLite file in the user data dir, reports are resolved to an absolute path under it, and SQLite writers take the lock up front.

## What was decided, and why

- **0076 — one list level per two spaces, depth clamped to the open-list stack**: a rule written down beats one inferred per document, and no indentation a model writes may unbalance our tags. → docs/decisions/0076-nested-lists.md
- **0085 — a length threshold (`$JOBSMITH_INLINE_ANSWER_MAX`, 2 000) decides chat vs file, not duration**: it is a reading budget, known exactly when the choice is made; a run with no file delivers its answer whatever the length. → docs/decisions/0085-answer-in-the-conversation.md
- **0085 — the report recites nothing about the run but its id**: the record (`jobsmith job <id>`) already holds it; `with_provenance` recites it for an archive. → docs/decisions/0085-answer-in-the-conversation.md
- **0074 — a job reference is a second input and port, not a wider `DocumentReader`**: a file and a run are two questions, and the file is the thinnest (and since #96 often absent) representation of the run. → docs/decisions/0074-prior-job-references.md
- **0096 — `_deliverable_wanted` is `bool(job.formats)`**: #85 removed the only reason a silent planned run needed a file; `None` and `[]` stay two facts. → docs/decisions/0096-no-document-unless-asked.md
- **0010 — a lease written before RUNNING, a pid only ever proves death, a cancel is a request the owner acts on**: a status written over a live run is overwritten by its next step; heartbeat 2 s, TTL 30 s. → docs/decisions/0010-cross-process-ownership.md
- **0010 — cross-process events are not built**: `BaseStore` cannot answer "what changed anywhere" without O(jobs) reads per subscriber; it is another `JobEvents` (#100). → docs/decisions/0010-cross-process-ownership.md
- **0063 — SQLite is a core dependency and the default**: "a file if the extra happens to be installed" would make one command behave differently on two machines. → docs/decisions/0063-persistent-by-default.md
- **0063 — `BEGIN IMMEDIATE` on the store's connection instead of a retry**: measured with five processes, the deferred `BEGIN` failed at once; the `_io` retry was removed after 40/40 green runs without it. → docs/decisions/0063-persistent-by-default.md
- **#98 took no decision of its own** (no record): the fix inspects the formatter's signature rather than catching `TypeError`, so the refusal the tests exist to catch cannot be swallowed.

## What to watch

- **CI installs from `pyproject.toml`, not `uv.lock`** (#98): a dependency released after the last green CI can break `main` with no commit; the provider-formatter tests only run with the chat extras.
- **Every process of a user now shares one SQLite file** (#63): a lock held past the 5 s busy timeout is raised, not retried — the first such report is a finding, not noise.
- **A deliverable growing an *Open questions* section** (#82, before this range): the caveats block becoming a section instead of landing on its sentences.
- **Users who relied on a `.md` next to every job** (#96): the README says it up front; `jobsmith run` now writes no file unless asked.
- The evals' answer checks moved off the file gate (#96): `test_the_answer_is_scored_on_more_runs_than_the_file` is the only guard of that shape.
