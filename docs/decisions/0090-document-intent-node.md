## From “Graph flow”

**Document intent** (`core/document.py`) is the second dedicated decision node, and it exists because the *request* had exactly one reader (#90). "compare X and Y, give me that as a PDF" produced markdown from `jobsmith run`, `/bg` and `POST /jobs`: the sentence was interpreted only by the chat model filling `launch_job`'s arguments, so #61's defect survived one door over from where #55 fixed it. All four doors go through the graph, so the decision belongs in it — folding it into the router's prompt is the rule this design is following, not a shortcut it may take. It answers in the three states `Job.formats` already has (names / `[]` / nothing) — its prompt offers a fourth answer, "a document, no format named", which resolves to the deployment's default *names* (`default_document_formats`, handed down by `build_app`, #96) so nothing downstream learns a fourth state — and writes **only to state**; `jobs/runner.py` translates that node's write into `FormatsChosen` and `JobManager._apply` folds it into the record, because `PostProcessor` and `Escalator` already establish that a node does not persist. Five properties hold it up. **It fills silence and never overrides**, structurally: `GraphRunner.stream` seeds `document_formats` with the job's own `formats`, and a value there returns the node before any model call — free, deterministic, and no second interpreter that can disagree with the chat model. **It cannot refuse**, which is why it is allowed to run where nobody is listening: #55 put both document refusals in `create_job` on purpose, and this node chooses from `available_formats(registry)` (handed down by `build_app`; `core/` never learns what a Reporter is) and drops anything else. **It is fail-open like the router** — bad JSON, an unknown answer, a format nothing renders, a dead provider: all of them write nothing, which since #96 means *no file*. That is the right side to fail on: a missing document is said on the record and the answer is delivered in full either way (#85), where an invented one is a file nobody asked for. **It sits BEFORE triage**, and that is the cost: one extra LLM call on every run whose caller named no format, on both routes. It buys the symmetry #84 already promises for a format that *was* named — a reader who asked for a PDF gets one whether the router sent their sentence to the planner or answered it on the spot — and this node needs only the query, so a later placement would serve one path and not the other. **It decides formats and nothing else**: `document_title` is derived mechanically from the request (#54) and a second, interpretive derivation beside it would need a rule saying which wins.

## From “Evaluating prompts (`evals/`)”

**`document_format` scores what the request asked for, in words** (#90), and like `document_as_requested` it is scored against the **case**: a job records the format it chose, so asking the record whether that was right is asking the defect to report itself. `EvalCase.expect_format` is the claim, and a format this deployment cannot render is a **skip** — `.[pdf]` needs pango where the run happens, so a golden case must not score a machine (`Observation.formats_available`, composed once per suite). The structural case asks for HTML rather than PDF for that same reason, and `KeywordLLM` reads the format names back out of the rendered prompt (`FORMAT_LINE`) and matches them against the request, exactly as `DIRECT_WORDS` lets it exercise triage — so the deterministic tier measures the wiring and never the fake's taste.
