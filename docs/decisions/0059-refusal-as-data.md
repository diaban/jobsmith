## From “Graph flow”

**A refusal is not an answer, and says so as data** (#59). A generator held to "use ONLY the provided material" must sometimes reply that the material does not answer the request — and that reply used to end the run exactly like an answer: `terminal_kind == "answer"`, job DONE, a report path announced in the chat, the person who waited three minutes finding out by reading the file. The decision the model already had to make is now asked of it **structurally**: `NO_ANSWER_INSTRUCTION` (`core/profile.py`) asks for one marker line, first line only, *only* on that path; `split_declaration` (`core/generation.py`) reads it, strips it and writes `answered: bool` into the state, and `_route_validate_output` sends a declared refusal to its own terminal node — the decision lives in the path map, like the empty plan's. Four properties hold it up. **Fail-open by construction**: the marker is asked for only when the model cannot answer, so a model that never emits it produces byte-for-byte today's run. **It is a protocol, not a grep**: only the first line is inspected, and only for the token the prompt asked for — an answer that merely *reads* like a refusal (in French, say, which is how this was found) stays an answer. **A refusal is never refined**: it is settled before the draft's validity, since re-running the generator against the same context can only repeat the refusal or invent the answer the declaration exists to prevent. **The job keeps everything** — it is DONE (`DELIVERED` in `jobs/manager.py`), results, usage, annexes and deliverable intact, `job.error` untouched because nothing went wrong; `terminal_kind` carries what kind of ending it was, and both Reporters open the file with `UNANSWERED_NOTICE` while `_notice_for` gives the chat its own branch. FAILED was rejected for the reason `_write_outputs` already gives about a failed write: it misreports the work, and it would throw away the one thing such a run has to hand back — the explanation of what was missing. A sixth `JobStatus` was rejected too: every consumer would have to learn it to say one thing `terminal_kind` already says. **What #59 did not say is where the bar is**, and the model set it at "I cannot verify": #73 states it in the prompt (nothing about the subject, not unverified material) and specifies what a refusal may contain. That is a change to the threshold and to the shape, and to nothing else here — the protocol, the reading, the routing and the fail-open are as described above.
