## From “Agents (`agents/`) — what an agent *is*”

**`slide_deck` is a generation, not a report format** (#35 step 2): a report is prose and a Reporter *serializes* it, while a deck is a different document — sections, one idea per slide, bullets, speaker notes. Slicing headings into slides gives bad decks, so the deck-shaped structure is **asked of the model**, which is thinking, which is why it lives here and not in `jobs/report*.py` — and its tokens are booked to the step like every other call. `slides.py` holds the `Deck`/`Slide` value types, the `DeckRenderer` port and the capability; `pptx_deck.py` is the only module that imports `python-pptx` (extra `.[pptx]`), exactly as `web.py` is the only one that speaks Tavily. It renders **16:9** (#62) — the stock template is 4:3, and resizing it is not one line: the template's placeholders are positioned for a 10-inch canvas and do not follow, so `_set_page` scales the horizontal geometry of the master and every layout by the same ratio, in **two passes** because a layout placeholder with no geometry of its own reports the master's and would be scaled twice (measured: a body 2.6 inches wider than its slide). `slide_width`/`slide_height` are class attributes, so 4:3 or A4-landscape is a subclass with two numbers. What a deck still cannot do is honour a request's *page* constraint: a deck is not paginated, and "one page, A4, 2.5 cm margins" has no meaning on a slide. Since #55 that is no longer a dead end — such a request asks for a **document**, and the format it wants is now something it can ask for — but nothing translates a page constraint into a deck, and nothing should: that request is not for a deck. Registered when a renderer AND an `ArtifactStore` exist (`_open_decks`), same rule as `documents`. **Its description says what it is NOT** (#61): a request for "a one-page printable synthesis, A4, as a PDF" was planned here and delivered a PowerPoint — nothing in the registry was closer, and a formatted sectioned document is a fair reading of a deck. The description is the whole of what the planner reads, so a capability that can be *mistaken* for another earns the same care as one nothing can serve, which stays out of the registry entirely. The other half of that issue was the request having no purchase on the deliverable's **format** — "as a PDF" reaching nothing at all — and #55 answered it: `formats` is a fact about the job, proposed and approved with the name, so a request for a printable PDF now produces one instead of the nearest thing in the registry. Its own decisions: the **job-less run is refused before the LLM call** (`job_id` is not Required on `CapabilityBaseState`; a deck nobody can store is not worth designing), a reply that is not JSON is **salvaged from prose** and marked `meta["via_fallback"]` — mechanical slicing is the fallback precisely because #35 argues it is a bad design — a **failed write declares nothing** (no path came back, and a ref to a maybe-file is what the manager refuses to record), and `emit_failure` still declares a path already in state, so a node added after `render` cannot orphan a file. The written report is still the deliverable; the deck is an `annex`. The **prose** stays the default agent's: an annex does not change what the final text is for, which is what `AgentProfile.generator_system_prompt` decides (#36). An agent whose *report* should read as a speaker's narrative is a different agent, and the capability is packable into one.

## From “Jobs layer (`jobs/`)”

**A capability can produce a file, and the job records it** (#35, step 1): `ArtifactStore` (`core/artifacts.py`) is the port — `async write(job_id, name, data) -> path` — and `LocalArtifactStore` the first adapter (`<reports_dir>/<job_id>/<name>`, composed in `build_app` and handed to the pack as `AgentContext.artifacts`). A capability takes it in its constructor like any other client, writes with `state.get("job_id", "")` (declared on `CapabilityBaseState`, NOT Required — a graph driven outside a job has none) plus a *filename*, and declares the result: `meta=artifact_meta(ArtifactRef(path, title=...))` — the `meta["artifacts"]` key `core/state.py` always documented. `JobManager._capability_outputs` reads the declarations back **in plan order** (`Job.ordered_results()`, since `results` arrives in wave order) and appends them to `job.outputs` as `role="annex", produced_by=<step>`. Four decisions worth keeping: **a port, not raw I/O** — where bytes go is a deployment decision, and a capability that calls `Path.write_bytes` can never be pointed at object storage nor faked in a test (same argument as `DocumentSource`); **a missing file is dropped and named in `job.error`** — recording it would repeat #28 (a deliverable nobody can open), staying silent would hide a capability defect behind a perfect-looking run, and the job stays DONE because the answer is the work; **annexes come after the deliverables and are never `main`**, so #28's one-main invariant and `report_path` are untouched, and they are collected even when the report write failed (the file is on disk either way); **one path is recorded once** (first declarer in plan order wins), because two `JobOutput`s for one file is the ambiguity `compose_reporters` already refuses. `with_annexes` is deliberately NOT extended to list produced files: a capability that wrote one already presents it through `render_report` — "a link to a file it produced" is what that docstring says — and the framework must not learn payload shapes.

## From “Adding a capability”

If it produces a **file** (`agents/default/slides.py` is the shipped example): take an `ArtifactStore` (`ctx.artifacts`) in the constructor, `await self.artifacts.write(state.get("job_id", ""), "chart.svg", data)`, and pass `meta=artifact_meta(ArtifactRef(path, title="…"))` to `_emit_success` — or to `_emit_failure`, if it wrote the file and broke afterwards. The job lists it as an annex whatever terminal the run reaches; never build a path yourself — `reports_dir` is the manager's.

## From “Testing conventions”

**The default registry is configuration-dependent**, so a test that pins what `KeywordLLM` plans (it chains every registered capability) must ask the composed app what it registered — `conftest.registered_capabilities(app)` — instead of hardcoding one environment. **Registered is not planned**: a step gated on `requires_inputs` (`read_files`) is in the registry and in the fake's chain, and the planner then drops it for a request carrying no such input, so that helper answers with the *ungated* set (`gated=True` for the whole registry) and `AgentApp.registry` is what lets it tell them apart. `slide_deck` made this real: with `.[pptx]` installed the fake plans a fourth step, and a hardcoded `{"research", "analysis", "critique"}` then passes under `make install` and fails in CI. The **order** of the registry is load-bearing for the same fake: it chains the capabilities as listed and plan validation prunes a dropped step's name from the surviving `depends_on`, so a gated step listed in the middle silently severs the chain around it — which is why `prior_jobs` and `read_files` are first in `default_capabilities` and why `grounding_reaches_reasoning` went to a *skip*, not a failure, when they were not.
